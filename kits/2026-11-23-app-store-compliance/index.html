Brutal Test Kit: mjmirza/app-store-compliance, "catch App Store and Google Play rejection causes before the reviewer does"

LEGIT* *free, 3-second, read-only scan that caught 8 of my 12 planted traps. It missed 4, including Premium sold through Razorpay. CLEAR is not an approval.

Tested 23 Nov 2026 on commit ad76746 (v2.5.1). The scanner is a bash script: no AI, no API key, 0 tokens. I ran it by hand exactly as the README's "Start here" says: bash agent-os/hooks/app-store-compliance-guard.sh "<app folder>", on a Linux VM.

The test app (a mini project, not a toy)

SplitBill, an expense splitter for trips and flats, iOS (SwiftUI) + Android (Kotlin): Google login, receipt photo read by OpenAI, a Rs 199 Premium (unlimited groups + CSV export), and bank-SMS reading to auto-mark UPI settlements. I hid 12 well-known rejection causes in it (GROUND_TRUTH.md), then made a fixed copy with all 12 fixed. It's a static test project: it is scanned, not built or submitted.

Why it missed what it missed

  • Razorpay. The iOS payment check (guard line 1044) is grep_has 'Stripe|PayPalCheckout|braintree|razorpay', which is case-sensitive. A payment link has none of those words. I then swapped in Razorpay's real iOS SDK (import Razorpay, RazorpayCheckout): still not flagged, 3/3. Same app with Stripe (import StripePaymentSheet): CRITICAL 3.1.1, 3/3. Same app with lowercase "razorpay" in the file: caught, 3/3.
  • Staging URL. The check matches staging\.[a-z] (line 912). staging.splitbill.dev is caught (3/3); staging-api.splitbill.dev is not.
  • Android account deletion. The pattern ANDROID-ACCOUNT-DELETION-URL is in data/rejection-patterns.json but appears nowhere in the guard script.
  • The 124. data/rejection-patterns.json has exactly 124 patterns (38 critical). 87 of the 124 IDs appear in the guard script; 37 don't. The guard's checks are hard-coded; it doesn't read that file to run them.

Fixed app: CLEAR, plus 3 HIGH warnings that didn't apply

0 critical, exit 0 (3/3 runs). It still printed: no privacy policy (the Android settings screen links https://splitbill.app/privacy), "UserDefaults used for sensitive credentials" (it matched the word "credential" in the Sign in with Apple code; UserDefaults only holds a user ID), and a Universal Links warning for the URL scheme Google Sign-In needs. The AI-consent reminder (MEDIUM) also stays even with a consent alert naming OpenAI.

Hook mode

Fed Claude Code's hook JSON on stdin: trap app + fastlane ios release or eas submit -p ios = exit 2 (block); git status = exit 0, silent. Fixed app: exit 0 for all. Not tested inside a live Claude Code session.
